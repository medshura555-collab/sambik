Python_LR1

Лабораторная работа по обработке, очистке и анализу данных с использованием Python.

Назначение проекта

Изучение методов чтения, очистки, сериализации и оптимизации больших наборов данных. Выполняется сравнение производительности библиотек "pandas" и "polars", а также систем управления базами данных SQLite и PostgreSQL.

Требования

- Python 3.12.10
- Git
- Visual Studio Code
- Расширения VS Code: Python, Pylance, Jupyter, Ruff, GitLens
- PostgreSQL — для выполнения этапа сравнения СУБД

Структура проекта

- "data/raw/" — исходные данные.
- "data/interim/" — промежуточные данные.
- "data/processed/" — обработанные данные.
- "notebooks/" — Jupyter-блокноты с этапами лабораторной работы.
- "src/" — исходный код и функции обработки данных.
- "sql/" — SQL-схемы для SQLite и PostgreSQL.
- "docs/" — документация и материалы отчёта.

Подготовка окружения

Клонировать репозиторий:

git clone <URL_репозитория>
cd Python_LR1

Создать виртуальное окружение:

py -3.12 -m venv .venv

Активировать его в Windows PowerShell:

.\.venv\Scripts\Activate.ps1

Установить зависимости:

pip install -r requirements.txt

Если файл "requirements.txt" отсутствует, необходимо установить зависимости, указанные в "pyproject.toml".

Запуск проекта

1. Открыть папку проекта в Visual Studio Code.
2. Выбрать интерпретатор Python из виртуального окружения ".venv".
3. Открыть нужный блокнот в каталоге "notebooks/".
4. Выполнять ячейки последовательно, соблюдая порядок этапов лабораторной работы.

Для запуска исходного кода при наличии соответствующего сценария:

python src/main.py

Основные этапы работы

- Чтение и первичный анализ данных.
- Очистка данных и обработка пропусков и выбросов.
- Сохранение и сравнение форматов хранения.
- Сравнение производительности "pandas" и "polars".
- Загрузка данных в SQLite и PostgreSQL.
- Создание индексов и выполнение контрольных SQL-запросов.
- Сравнение времени выполнения запросов и размеров баз данных.

Данные и безопасность

Большие исходные файлы, промежуточные результаты, файлы баз данных, виртуальное окружение и секретные параметры подключения не должны попадать в Git-репозиторий.

Для подключения к PostgreSQL следует использовать собственные параметры подключения. Пароли и другие секретные данные нельзя сохранять в открытом виде в репозитории.

Результат

Результаты измерений, сравнительные таблицы и выводы представлены в материалах лабораторной работы и соответствующих Jupyter-блокнотах.
